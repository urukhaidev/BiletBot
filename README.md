# Bilet Bot — Python

Перенос Telegram-бота из предоставленного n8n workflow. Python 3.11+.

## Возможности

- Поиск на русском через OpenAI-совместимый API; города через Travelpayouts autocomplete.
- Travelpayouts GraphQL: в одну сторону и туда-обратно, точные даты, месяц, диапазон вылета, длительность, прямые рейсы, багаж, максимальная стоимость.
- Порог цены: текущая, −5%, −10%, −20% или своя цена.
- Фоновая проверка при запуске и затем каждые 30 минут по умолчанию.
- Постоянные подписки, история проверок и состояние ввода своей цены в SQLite.
- `/alerts`, `/history`, `/cancel`, `/delete_alert_id_N`; `/info` для администратора.
- Туристические рекомендации по префиксам «что посмотреть», «куда сходить» и т. п.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e '.[test]'
cp .env.example .env
# Заполните .env своими ключами
python -m biletbot
```

Обязательные переменные: `TELEGRAM_BOT_TOKEN`, `TRAVELPAYOUTS_TOKEN`, `LLM_API_KEY`.
Для OpenRouter задайте `LLM_BASE_URL=https://openrouter.ai/api/v1` и доступный вам `LLM_MODEL`.
Travelpayouts-токен должен иметь доступ к GraphQL API, используемому в исходном workflow.
`CHECK_INTERVAL_SECONDS` задаёт период проверок, `API_REQUEST_INTERVAL_SECONDS` — паузу между запросами Travelpayouts.
`ADMIN_USER_ID` — Telegram ID администратора. Остальные параметры описаны в `.env.example`.

Docker:

```bash
docker compose up -d --build
docker compose logs -f bot
```

Для одного Telegram-токена запускайте один экземпляр бота. Отключите Telegram Trigger старого n8n workflow и удалите его webhook перед переходом на polling (метод Telegram Bot API `deleteWebhook`). Каталог `data/` сохраняйте между перезапусками и резервируйте: там подписки и история.

## Как устроено отслеживание

### Режимы поиска

| Режим | Условия | Пример |
| --- | --- | --- |
| OW_DATE | В одну сторону, точная дата | Москва Сочи 10 ноября |
| OW_MONTH | В одну сторону, месяц | Москва Сочи в ноябре |
| OW_RANGE | В одну сторону, диапазон вылета | Москва Сочи вылет с 10 по 20 ноября |
| RT_DATES | Туда-обратно, точные даты вылета и возврата | Москва Сочи туда 10 ноября обратно 20 ноября |
| RT_DATE_DUR | Туда-обратно, точный вылет и длительность | Москва Сочи 10 ноября на 7–9 дней |
| RT_MONTH | Туда-обратно, месяц и длительность | Москва Сочи в ноябре на 7–9 дней |
| RT_RANGE | Туда-обратно, диапазон вылета и длительность | Москва Сочи в середине ноября на 7–9 дней |

Без дат используется текущий месяц. Для RT без длительности и без точной даты возврата используется 7–10 дней. Прямой рейс, багаж и максимальная цена — фильтры для каждого режима.

Для точного вылета показывается один самый дешёвый вариант каждого запрошенного типа. Для гибких дат — до трёх вариантов. Если тип поездки не указан, бот всегда делает две подборки: OW и RT (RT по умолчанию 7–10 дней), с независимыми кнопками подписки. Это действует и для точного вылета: один OW и один RT с гибким возвратом. Билеты в таблице и описаниях не нумеруются.

Выдача отправляется через Telegram Bot API `sendRichMessage`: нативная таблица (`InputRichBlockTable`), изображения (`InputRichBlockPhoto`), описания и ссылки внутри одного сообщения. Даты с русскими названиями месяцев, расшифровка багажа, места и длительность пересадок, время в пути (для RT отдельно по направлениям, если API предоставляет сегменты). Режим указан снизу в footer. `0PC` означает отсутствие зарегистрированного багажа; норму ручной клади API этим полем не сообщает.

Обе подборки объединяются в одно Rich Message. Одна бело-синяя PNG-карточка первого найденного билета размещается в начале, затем идут таблицы и детали OW и RT, внизу — режимы и независимые кнопки подписки. Например, «Москва Бангкок в октябре» даёт до трёх дешёвых OW и до трёх RT за октябрь; без месяца используется текущий месяц. Для запуска вне Docker нужны шрифты DejaVu (`fonts-dejavu-core` в Debian/Ubuntu). Это карточка предложения, а не документ для посадки. Новые методы вызываются напрямую через HTTP, поскольку установленная Telegram-библиотека ещё не содержит классы Rich Messages.

Интерактивный поиск получает первую страницу (до 400 записей, сортировка по цене); мониторинг проверяет все страницы. Названия городов определяются параллельно и кэшируются. В журнале доступны длительности этапов LLM, определения городов и поиска билетов без ключей и текста запросов.

Сохраняется полный нормализованный поиск, включая RT и даты возврата. Повторные проверки не вызывают LLM: условия не меняются. Билеты дополнительно проверяются локально на соответствие датам, маршруту, багажу, пересадкам и длительности.

Цена сравнивается без округления, строго **меньше** порога. Уведомление повторяется только при цене ниже последней успешно отправленной. При отсутствии билетов подписка остаётся активной. Ошибка API или отправки не считается успешным уведомлением: следующая проверка повторит попытку. Подписки на прошедшие даты отключаются; если пользователь заблокировал бота, его подписка отключается.

История цен хранится в `price_history`; `alerts.checked_at` и `last_error` показывают состояние проверки. После перезапуска сохраняется защита от повторных уведомлений. При аварийном завершении непосредственно после доставки, но до записи результата в БД, уведомление может повториться: Telegram не предоставляет идемпотентную отправку.

Данные API кэшированные, как и в n8n: уведомление означает найденную цену в Travelpayouts, а окончательная стоимость проверяется на сайте продавца.

## Отличия и перенос данных

В предоставленном workflow не было планировщика проверки подписок; здесь он реализован. Исправлено сохранение RT вместо постоянного OW, исключён фиксированный получатель сообщений, цена не округляется до сотен, даты берутся из ответа API с годом.

Используется новая SQLite-база. Существующие таблицы Supabase (`alerts`, `avia_searches`, `cheaptickets`, справочник `aviasales`) автоматически не импортируются. Для переноса старых подписок нужны экспорт таблиц и их схема: их нет в присланном JSON. IATA определяется через autocomplete; пользовательские теги и направления-страны из старого справочника требуют отдельного переноса. Старые кнопки из n8n привязаны к старым ID: создайте подписки новым поиском. В выдаче есть ссылка Aviasales; партнёрские ссылки Trip.com из старого workflow не перенесены.

Ключи задаются через окружение; токены из JSON не встроены в код.
